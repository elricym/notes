## 一、整体分工（核心思路）

这是一条多个模型分工的流水线，每个工具只做它最擅长的一段：

| 环节 | 工具 | 作用 |
|---|---|---|
| 需求 / PRD | Fable 5.1 | 梳理核心场景、人物、剧情线 |
| 概念图 | (GPT) Image 2.5 | 场景图、人物多视图 |
| 3D 资产 | Tripo（道具用 H3.1，人物用 Smart Mesh P2.0） | 生成核心模型 |
| 建模 / 代码 | Opus 5.5 | 通过 CLI/MCP 操控 Blender + Unity，搭建核心代码 |
| 迭代修 bug | Astra | 优化与调试 |

**环境准备：**
- Blender CLI，加付费插件 Auto-Rig Pro，用来绑骨和蒙皮。
- Unity App 和 Unity CLI，项目里装 Pipeline 包，让 Claude 通过官方 Unity MCP 直接操作工程。

关键在于让 AI 直接操作 Blender 和 Unity，而不只是写代码让人去粘贴。

## 二、场景构建：参考图 → 拆资产 → AI 建模 + 盲审迭代

1. **先定一张满意的效果图，再补其他视角。** 俯视图说明布局，斜侧视图补充高度和层次。有室内也有室外的场景尤其需要多视角。
   > 提示词：基于上传的场景参考图，帮我生成一张该场景的全面貌参考图片，包括整体环境的多视角视图以及局部细节的展示。
2. **让 AI 判断哪些资产交给 Tripo 生成，哪些在 Blender 里直接搭**，并在图上标出来供人确认。这样能省下 Tripo 的额度，也避免简单几何体被过度生成。
3. **把 Tripo 资产和参考图交给 Opus 5.5 去复刻场景**，再按多机位截图逐步修正。最值得借鉴的是作者要求 **“派一个独立的审查 agent 做多机位盲审”**，和参考图有差异就继续迭代。这相当于用评审 agent 给生成 agent 做闭环。

## 三、人物：多视图 → 3D → 绑骨 → 动作 → 精修

1. 用 Image 2.5 生成 **T-pose 四视图**，各视角的细节要一致。
2. 在 Tripo 里选「多视图生成 3D」，用 **Smart Mesh P2.0** 生成。
   - 拓扑选四边形，精度拉满。
   - P2.0 的卖点是面数可控、方便编辑，适合后面绑骨。
   - 白模网格没问题就点 Texture 生成贴图；网格不合理就用 edit mesh 局部重生成。
3. 用 Auto-Rig Pro 自动绑骨和蒙皮，然后测试抬手、弯腿、转身，修正变形和穿模。
4. 从 [Mixamo](https://www.mixamo.com/) 下载 FBX 动作，让 Opus 检查骨骼是否匹配并接入。
5. **复杂交互**（例如小王子提水壶）Mixamo 没有现成动作。做法是先挑一个接近的基础动作，再让 Opus 用 Auto-Rig Pro 的手臂 IK 控制器调整握持，避免穿模、脱手或水壶悬空。

## 四、我的判断 / 适用条件

- **适合：** 风格化、低多边形、小场景的叙事或探索类独立游戏和 demo。资产数量少，对美术一致性的要求可以靠参考图兜住。
- **不适合（文中没覆盖）：** 性能优化、大规模关卡、多人联网、玩法平衡等。文中也没有给出耗时、成本（Tripo credits、模型 token）和失败率。
- **可迁移的方法论：**
  - 先用图把需求定成明确的画面，再拆资产。
  - 生成 agent 和独立审查 agent 组成闭环。
  - 通过 MCP 或 CLI 让模型直接操作专业软件。
- **门槛：** 需要 Unity、Blender 和 Auto-Rig Pro（付费插件）的基础操作能力。“全交给 AI”有夸张成分，选资产、确认标注、看截图反馈仍然要人来做。
