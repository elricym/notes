## 三、工程产品

### [Uber’s AI infra, from the inside](https://newsletter.pragmaticengineer.com/p/ubers-ai-infra-from-the-inside)
The Pragmatic Engineer（Gergely Orosz）× Uber Distinguished Engineer Uday Kiran Medisetty｜10/15 01:06（北京时间）｜播客深度访谈，邮件里有 11 条 takeaways 和完整时间轴。

**核心论点**：Uber 看上去一年内搭好了整套 AI 工程设施，其实是站在过去十年开发者工具上的。对工程师来说，工作越来越变成「给 agent 建对上下文」；对平台来说，统一的 Model Gateway、混合预算和按类型打标签的 PR，比单纯追 PR 数量更有意义。

**平台与规模背景**：
- 2015 年 Uday 入职时只有约 2 个服务，2019 年涨到数千个；到 2026 年服务数大致持平，但业务规模约是当年的 10 倍。
- 很多系统不得不自研：uOwn（服务归属）、M3DB（约 5 亿指标/秒，后来 Chronosphere 建立在开源版上）、Cadence（多日工作流，Temporal 由此而来）、Morpheus（特性开关 + 实验，含双边/三边市场的 switchback）。
- 「城市」是一等公民：可观测、特性开关、部署、甚至早期数据库分片都按城市建模；每个城市钉在某个云区域，可随时故障转移到另一区域。

**AI 基础设施**：
- **Model Gateway（2023）**：强制模型与 harness 无关，可在 Anthropic、OpenAI、自建开源模型间切换；上面挂了 AI Guard（安全中间件）、按用户计费、审计与 session trace。
- **AIFX（AI Foundations）**：包在 Claude Code、Codex、OpenCode 之上，换 harness 时设置、skills、插件跟着走。
- **混合花费**：工程师有花费档位，触顶后经理可加额度；CostCheck 插件跨 session 给省 token 建议，近几个月 token 成本约降 50%。
- **CI「code red」**：12 个月内 CI 任务翻倍以上；简单校验（lint、build、模板规则）挪进「内环」，agent 用 `afx validate` 开 PR 前先跑。

**人怎么干活、怎么量**：
- 所有 PR 仍由人审，但会先跑 AI review、附截图/视频（适用时）、打风险分，帮评审决定该花多少时间。
- 不再只看「diff 到生产要多久」：按 feature / bugfix / maintenance / testing / docs 打标签；feature PR 占比在升，maintenance 在降。
- Uday 对工程师角色的概括：上下文工程、多任务并行、以及审查并挑出 agent 代码味道，避免把回归送进生产——这些比以前更重要。
- Minion（2025）建立在 2017 的 DevPods 上；MCP Gateway 能快，是因为已有 Thrift/Protobuf 注册表。Uday 的原话大意是：过去方便工程师的东西，现在同样方便 agent。

**用法**：
- 想做内部 agent 平台，优先看统一网关 + 安全中间件 + 花费可见性，而不是先堆多个聊天窗。
- 衡量 AI 提效时，用 PR 类型占比和业务影响，比 PR 速度更稳。
- 延伸：同系列 [How Uber uses AI for development](https://newsletter.pragmaticengineer.com/p/how-uber-uses-ai-for-development)。

> **个人评注**：这篇把「十年平台债突然变成 AI 资产」讲得很清楚。如果公司内部还没有服务归属、工作流引擎、可观测和实验平台，硬上 agent 很容易卡在上下文和权限上，而不是卡在模型本身。
