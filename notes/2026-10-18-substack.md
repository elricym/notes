**1. 离职时要不要行权创业公司期权？**

Rafael Pereyra 在一家公司待了 8 年，已归属的期权是在估值最高点授予的，离职后只有 3 个月窗口决定是否掏钱行权。

- Jon Roemer 的判断框架：行权本质上是赌博，只投你能接受全亏的钱。想要 4–10% 的回报，指数基金、定存、高息储蓄都能做到；如果手上有利率高于 4–10% 的债务，先还债的回报比任何投资都高。
- Tamara Ceman 两次放弃了数额不小的已归属期权（第二次请了理财顾问评估），事后看都对：一家公司以低于行权价的价格被卖掉，另一家仍未上市、任何股份出售都要董事会批准。她的教训是：以后的合同必须写明延长行权窗口，最少 3 年，理想 10 年。
- Priya Mathew Badger：早期公司一般给期权，后期公司给 RSU。她也两次放弃期权，手上后期公司的 RSU 有 7 年有效期，大概率在退出前就过期了。一位朋友行权后在私募收购时拿到回报，但收益和同期投标普 500 差不多。建议：像天使投资人一样重新审视公司；非流动性股权只当"蛋糕上的糖霜"，去早期公司应该是为了岗位范围和 0 到 1 的机会，并确保现金薪酬本身够用。

**可执行结论：** 谈 offer 时争取 3–10 年的行权窗口；决定行权前，把这笔钱和"还高息债务"或"买指数基金"的回报直接比较。

**2. 怎么持续追踪竞品的营销口径？**

Natalie A. Thomas 想给客户搭一套持续扫描竞品的系统，覆盖功能发布、公关叙事、广告的周/月/季变化，以及官网、落地页和帮助文档的改动。

- Keyur Shah 用 Krama（krama-ai.com）加 Grok Bot。
- Kourtney Rose 给出了最完整的方案：
  - 用 Claude routine 每天扫描所有竞品网站的关键页面，截图并报告改动，挑出有意义的变化，每天早上发邮件。之前用的 Fruitful 似乎倒闭了，Yutori Scouts 也在下线，所以都迁到了 Claude routine。
  - 另一个 routine 搜索 newsletter、社交媒体/LinkedIn 和行业媒体，重点看竞品动向，包括公司员工的公开发言，用来发现人事和岗位变动。
  - 用一个小号邮箱订阅所有竞品的 newsletter 和邮件列表，转发到个人邮箱的一个文件夹，agent 出报告前会先读这个文件夹。
  - 早上一个汇总 agent 发一条很短的 Slack 消息，附当天的 Google Doc 报告（含所有链接和来源）；文档按日期归档，另有一张总表索引所有报告。
- Elizabeth Fleming 也在考虑用 agent 定时扫描，包括 CEO 和高管的公开发言。

**可执行结论：** Kourtney 的四层结构（网页改动截图、新闻与社媒、小号订阅竞品邮件、早报汇总）可以直接照搬。

**3. 给 AI agent 写 PRD**

KT 问：团队在为产品里的 agent 功能写 PRD 吗？要不要像 [Calibre 的文章](https://blog.calibrelabs.ai/p/an-eval-rubric-that-drives-your-ai) 建议的那样，在 PRD 里加一版初步的 eval 评分标准？

- Paul Howard：PRD 依然是对齐工具（解决什么问题、为谁、测试什么方案、要推动什么结果）。agent 产品要额外加一版初步的 eval 评分标准：什么算好、哪些失败一开始就不可接受、怎么判断它在起作用。但别指望一次写对，有了原型之后，trace（运行轨迹）会暴露没预料到的行为和失败模式，这些应该反过来改 eval、PRD，甚至产品本身。PRD、原型、trace、eval 是同一个学习循环。
- Hunter：给 agent 写的 PRD 花的时间可能比给人写的还多，因为规格一旦有模糊空间，agent 就会钻空子把任务搞砸。
- 关于多个 PRD 版本怎么协调，Paul 建议：当作活文档，但要显式标版本号；agent 永远只读当前版本，旧版本作为历史保存，而不是互相竞争的"真相来源"。

**可执行结论：** agent 产品的 PRD 加一节"eval 初稿"（好的标准 + 不可接受的失败），原型跑出 trace 后迭代；文档显式版本化。

**4. 软件还有长期护城河吗？**

Abdussamad Bello 认为团队、算法、数据、营销、速度、设计、成本这些传统优势都在消失。

- Quai：受众是一条，比如 Lenny 的社区，做什么都自带分发。
- Hunter：过去几十年软件里本来就没多少持久护城河，关键是抓住机会、变现、再转向下一个机会。他认为 Figma 的护城河已大幅被填平，Linear、Bubble 没有护城河，Zapier 已经商品化；HubSpot 和 Salesforce 有，但 Salesforce 是靠收购 Slack 这类公司不断"移动"来维持的。
- Abdussamad 补充数据：Zapier 巅峰时 60% 的财富 500 强在用，但他也承认这些护城河现在已经消失。
- Anthony DeLuise 推荐了 [Gokul Rajaram 谈八种护城河](https://www.usetranscribe.io/yt/6ctOnY1WmBw/gokul-rajaram-eight-moats)：护城河从来不止一种，而且一切都建立在用户愿意回来用的好产品之上。
- Josh Herzig-Marx：唯一长期的护城河是商业模式。
- Abdussamad 推荐了 Lenny 的旧文 [How to tell if a startup has a moat](https://www.lennysnewsletter.com/p/how-to-tell-if-a-startup-has-a-moat)。
