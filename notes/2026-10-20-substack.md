### [How I AI: Meta Muse Wonder + How Brooke Lacey is scaling video with AI](https://www.lennysnewsletter.com/p/how-i-ai-meta-muse-wonder-how-brooke)

**第一集：Meta 新模型 Muse Wonder 实测——适合做 agent，别让它碰设计**

Claire 用近 20 个真实任务测了 Muse Wonder，覆盖 agent 工作、编程、写作、设计和视频剪辑，并和 Opus 5.5、Astra、Fable 对比。

1. **同价位里最强的 agent 模型。** 在账单工单处理、收件箱分拣、电脑操作、写邮件四项上排第一。优势在长任务上最明显：它会不断换方法，直到达成目标。
2. **"active focus"（主动专注模式）是真本事。** 复杂任务它会花更多时间，简单请求很快；而且花的时间和产出质量的对应关系，比竞品更清晰。
3. **账单工单测试能看出 agent 能否在真实 SaaS 环境里干活。** Muse 修正了账号关联错误、处理了重复退款逻辑、改了客户套餐、起草回复并关单；还挡住了一次提示词注入，所有预埋的坑都解决了。
4. **写邮件可以放心交给它。** 能贴合 Claire 两句话的简洁风格，不变正式、不啰嗦；语音表现也自然，接近 Sonnet 的水平。
5. **前端设计不要用它。** 默认厚重衬线字体、蓝紫色、圆角、通用 SaaS 布局。做 ChatPRD 改版时无视品牌规范、加 emoji、图片渲染坏掉，和原站脱节。
6. **原型做到 80% 和做完是两回事。** 脚手架很像样，但交互测试时按钮失效、主题错误、浮层挡住内容。弱点不在生成界面，而在视觉打磨和功能完整度。
7. **视频剪辑有直觉、执行弱。** 选对了 40 秒片段、配乐 Claire 喜欢、剪点时机也接近；但叠加层、字幕位置和音频处理拖了后腿。
8. **速度看任务。** SVG、短原型等一次性请求很快；收件箱分拣、后端实现、视频剪辑明显变慢，可能是 active focus 在复杂任务上多花了时间。
9. **结论：** 进入 Claire 的实验清单，但不当日常主力。她打算在几个 agent 工作流里试，尤其看好个人 agent 和知识工作编排，前提是不涉及设计。

**第二集：Brooke Lacey 用 Claude Code 剪 TikTok**

Brooke 是资深技术人和创作者，TikTok 粉丝 29 万以上。她用 Claude Code + FFmpeg + Whisper，把手机原始录像在约 15 秒内变成带字幕的成片，不上传素材、不开剪辑软件。

1. **终端 + 三个工具替代剪辑软件。** FFmpeg、Whisper、Python，由 Claude Code 编排。原始视频进去，约 15 秒出竖屏短视频，带字幕、跳切和推镜。
2. **整个剪辑存在一个文本文件里。** 一个 TSV，每行是一个剪辑点：开始时间、结束时间、景别、标签。有了这个文件，同一条命令能从一条原始素材生成 15/30/60 秒三个版本，外加横屏裁切。
3. **教 Claude 认出她的喜剧节奏。** 不只是剪掉静音，而是学她的语调节奏、包袱前的停顿、词后的最佳剪点、多次重拍里哪条节奏最好。这靠反复指导和迭代，不是一个巧妙提示词。
4. **评论区就是选题简报。** 把每条视频和它的评论配对，让 Claude Code 找出观众质疑、争论或想看下一步的内容，产出基于真实受众信号的新选题。
5. **先懂手艺，才能交给 AI。** 她能教会 Claude，是因为她本来就知道好剪点听起来什么样、推镜落在哪、为什么节奏重要。
6. **个人 AI 操作系统比提示词合集好用。** 她的 "lane OS" 给每个产品配独立的记忆、权限和状态文件；出错时追溯到相关指令，并把修正写进全局，防止重犯。
7. **每周发一条也够。** 她大约每周更新，老视频还会反复被推。Claude Code 没让她发得更多，而是省下了每条视频要花一整天的剪辑时间。

延伸阅读：[本集博文](https://www.chatprd.ai/how-i-ai/brooke-lacey-claude-code-video-editing)、[用 Claude Code/FFmpeg/Whisper 自动剪短视频](https://www.chatprd.ai/how-i-ai/workflows/claude-code-short-form-video-editing)、[用 Claude 分析 TikTok 评论找选题](https://www.chatprd.ai/how-i-ai/workflows/claude-tiktok-comments-content-ideas)。

**可执行结论：**

- 选 agent 模型时，拿一个带"预埋坑"的真实工单（账号错误、重复退款、提示词注入）来测，比跑分更能看出能不能上生产。
- 把重复性的创作流程改成"结构化文本文件 + 一条命令"：一次决策（TSV），多种产出（不同长度、不同画幅）。
- 给 AI 搭工作系统时，按项目隔离记忆和权限，每次纠错都沉淀成全局规则。

### [Deep|LLM: Enterprise AI Adoption Survey (Vol. 6) - In Our Sample: AI Spending Growth Expected to Slow; Routine Wor…](https://fundaai.substack.com/p/deepllm-enterprise-ai-adoption-survey-c2c)

FundaAI｜10/20 00:29（北京时间）｜样本 6 家公司，访谈时间 9/19–10/11｜付费内容，最后一节（各公司 2027 支出展望对比）被截断

- **支出增速多数放缓。** 金融科技初期铺开后放缓；制药靠更好的选型和重谈采购条款压增速；药房与健康保险集团大致持平。
- **Claude 工作流替代专业软件。** 车贷公司自建的 Claude 特征工程流程（指定表和变量组合、要求解释业务含义、考虑合规），准备停掉每年约 8–10 万美元的专业工具。专家原话："这工具显然已经多余了。"
- **按任务选模型：花得少、用得多。** 金融科技部分团队经选型培训后支出约减半，token 用量反而上升；专家估计更好的选型至少能省 30%。药房与健康保险集团估计把分类和抽取从 Sonnet/Opus 挪到 Haiku 或开源模型，可省 API 成本 20%–30%（以当前每月约 4.5 万美元计，约 0.9–1.4 万美元）；清理上下文、缓存、缩短提示词、减少无效 agent 循环，还能再降 10%–20% 的 token 量。
- **追加预算要算回报。** 啤酒集团要求每 1 美元带来 2–3 美元的降本或增收，并要业务方承诺改流程、减编制。金融科技每季度复盘部门 AI 支出和产出。
- **API 支出在核心流程里增长。** 药房与健康保险集团月 API 支出半年内从约 2–2.5 万涨到约 4.5 万美元，占订阅+API 的比例从约 20% 升到 30%；订阅从约 9–9.5 万涨到约 10.5 万。制药集团则反过来，订阅占比从年初约 20% 升到约 75%。
- **数据平台受益。** 药房与健康保险集团 Databricks、Snowflake 和云数据基础设施合计月成本从半年前约 2–2.5 万涨到 3.5–4 万美元，预计再过半年 5–6 万。体育流媒体用 Snowflake Cortex 做自然语言分析；计划通过 Google Workspace 给全员开 Gemini；开发仍用 Claude Code，原因是"它先到的，大家用惯了"；同时提议削减 Atlassian（Jira、Confluence）支出。
- **开源自托管。** 制药集团开源模型已承担约 50% 的 API 调用（环比 +20%），专家粗估成本比外部 API 低约 90%（不含内部部署运维成本）。金融科技开源占 API 支出约 5%，预计 2026 年底 5%–10%、2027 年底 50% 以上。药房与健康保险集团开源占 API 支出约 25%、用量 35%，预计 2026 年底 35%、2027 年底 45%。阻力：体育流媒体担心"坏了找谁"；车贷公司出于安全和隐私暂不考虑。
- **前沿模型。** 多数公司未把 Fable 用于日常生产（成本、缺少值得用的重复任务、数据保留条款）；啤酒集团用 Astra 做跨系统的商业分析。啤酒集团专家认为中档或小型开源模型够应付 70%–80% 的任务；药房与健康保险集团专家估计真正需要最强模型的难题约占 10%–20%。
- **ROI 实例。** 复杂理赔处理时间缩短 20% 以上；护理文书辅助每位护士每天最多省约 90 分钟（尚未量化净财务回报）。车贷公司用 LLM 读论文、复现算法、拿内部数据测试，30–60 分钟能测 5–10 篇论文的算法，过去每篇约一周；放贷决策仍用传统机器学习（要可解释、过监管审计）。语音 AI 处理逾期 1–2 周的还款提醒，减少了扩招客服的需要。

**可执行结论：** 先做模型路由（简单任务走便宜模型、隐藏手动选最贵模型的入口），再看开源自托管；为 AI 追加预算时，用"每 1 美元换几美元降本/增收"作门槛。
